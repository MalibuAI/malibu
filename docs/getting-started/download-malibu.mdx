# Download Malibu

> A signed, notarized Mac app for providers. Registering a new Mac needs an invite.

The Malibu app is the main way to join the network as a provider. It ships as a signed and notarized `.dmg`. The app bundles the provider CLI and manages it for you, so you don't need a terminal.

<Note>
  **Private pre-beta.** The download is public, but **admission is not**. You need a valid invite code (links look like `malibu.tech/j#/…`) to register a new Mac. Providers that are already running keep updating without a new invite. Troubleshooting: [malibu.tech/host/troubleshoot](https://malibu.tech/host/troubleshoot).
</Note>

## What onboarding looks like

1. **Open your invite.** Use the link you were sent, then download the DMG, drag Malibu to Applications, and launch it.
2. **Paste the invite code and click Launch Provider.** This is the only step you take yourself. From here Malibu:
   * installs the provider software;
   * benchmarks your Mac and picks the best paid model that fits its memory, from the signed [model catalog](/operations/model-catalog);
   * downloads the model and verifies it against the catalog hash;
   * registers the Mac with the network.

   The first run can take a while, mostly model download and local checks.
3. **Provider live.** The app shows the model in use. New Macs join the **provisional** routing tier until they meet the criteria for **trusted**. See [Payments → Routing tiers](/guides/payments#routing-tiers).
4. **Open the dashboard.** The dashboard shows today's credits, the current model, and the model-recommendation status. From there you can change models, add a payout wallet address, and repair or update the provider software.

You don't need a wallet to start. Payouts are off until public beta, and adding a wallet only registers an address.

## What you get

* **Automatic model choice.** It is matched to your Mac's unified memory and measured throughput and latency. When a better paid model becomes available, the dashboard offers it and you choose **Adopt** or **Not now**.
* **Automatic updates.** New signed releases are verified, in-flight requests drain, and the provider and app are swapped in place. See [Provider autoupdate](/operations/provider-autoupdate). **Check for Updates…** in the menu bar runs an update on demand.
* **Menu-bar controls.** Status, today's credits, **Pause** / **Resume**, **Open Dashboard**, **Export Diagnostics…** (a redacted support bundle), **Reset Provider Service…**, and **Quit and Uninstall…**.
* **90% provider share** of billed credits on verified requests. **USDC-on-Base payout is planned for public beta and is off in pre-beta.** You can register a payout wallet address now; it does not send funds. See [Payments & payouts](/guides/payments) and [Economics](/guides/economics).

## Requirements

* Apple Silicon Mac (M1, M2, M3, M4, or M5)
* macOS 14 Sonoma or later
* Unified memory: 8 GB can serve the 3B catalog row, 16 GB+ is recommended, and 32 GB+ opens more of the current catalog. Per-model floors are on the [Model catalog](/operations/model-catalog) page.
* Wired or fast Wi-Fi.
* **Invite code** for a first-time registration

The provider connects **outbound** only, so you need no port forwarding, static IP, or inbound firewall rules.

If no paid model clears on your Mac, setup does not start a paid provider and the app tells you so. The app has no donor-mode action; the donor-mode prompt appears only in an interactive terminal install.

## Uninstall

Use **Quit and Uninstall…** from the menu bar. It removes the background provider, Malibu settings, and the local provider setup. It keeps your saved provider access, so reinstalling doesn't need a new invite. It deletes downloaded models in `~/Library/Application Support/macprovider/models`; only the Hugging Face cache is kept.

## Headless install

For a remote Mac, an SSH-only Mac mini, or a terminal-only setup, use the [headless install](/cli/headless-install). It uses the same provider CLI without the app UI. Fresh headless installs still need an invite.

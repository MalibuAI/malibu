# Benchmarks & methodology

> Evidence behind hardware and mining claims in the [Litepaper](/litepaper). **Last reviewed:** 23 September 2026.

Malibu publishes two different performance stories. They must not be conflated:

| Workload | What it measures | Where it is used |
| --- | --- | --- |
| **PoMW memory-hard walk** | 256-step walk over canonical GGUF weights on Metal | Mining readiness, token emission (planned v0; not in the production provider runtime) |
| **Inference serving** | Tokens/sec on buyer chat completions | Marketplace economics (live today) |

A strong PoMW walk result does **not** automatically imply the same per-watt advantage on inference TPS. This page scopes the published PoMW numbers.

## PoMW Phase 1 benchmark (M5 Air)

Source: internal Phase 1 Metal port run (results captured July 2026 on an **M5 Air**). The plan it followed is [`mining-prototype-phase1.md`](https://github.com/MalibuAI/malibu/blob/main/mining-prototype-phase1.md). The results report itself and the raw benchmark JSON are **not yet published**, so treat these numbers as unaudited internal measurements until they are.

| Metric | Result | Notes |
| --- | --- | --- |
| Walk throughput | **2.14M walks/s** sustained | 256-step memory-hard walk over Qwen3-1.7B GGUF weights |
| Power draw | **4.7 W** | Sampled during sustained walk harness |
| Determinism | **200 vectors** byte-exact | Metal output matched Rust CPU reference |
| Model | Qwen3-1.7B (GGUF) | Same weight file family used for walk verification |

### What this proves

- The PoMW algorithm runs correctly and efficiently on Apple Silicon Metal.
- The walk is memory-substrate bound — the workload Malibu targets for mining readiness.
- Byte-exact determinism against a reference implementation is reproducible.

### What this does **not** prove

- Inference tokens/sec on buyer workloads.
- That every Mac tier sustains the same thermal profile (fanless Air throttles under long runs).
- Cross-hardware superiority on workloads other than this specific walk.

## 10× per-watt vs RTX 5090 (scoped claim)

The Litepaper cites roughly **10× better per-watt efficiency vs an RTX 5090** on **PoMW memory-hard weight walks only** — not on inference TPS.

| Dimension | PoMW walk (M5 Air) | RTX 5090 comparison |
| --- | --- | --- |
| Workload | 256-step weight walk | Same algorithm class, different substrate |
| Metric | walks/s ÷ watts | Directional context only |
| Inference | **Not measured here** | **Not measured here** |

**Methodology note:** GPU numbers use the same walk algorithm ported to the comparison substrate where available. The RTX 5090 measurement and its methodology are not yet published, so this ratio is directional, not audited. This is a **mining-substrate** comparison, not a buyer inference benchmark. Do not extrapolate to chat-completion pricing or latency.

## Inference benchmarks (not yet published)

Malibu does **not** publish a cross-tier inference TPS table on `/docs`. What exists today:

- **Console bill line** — client-measured decode tok/s for a single stream (not network-wide).
- **Public stats** — `GET https://api.malibu.tech/v1/stats/overview` has volume, pool size, estimated capacity and utilization, plus network-wide tokens per minute over the last 30 minutes (`timeseries.tpm_30m`). There is no per-provider tokens/sec figure.
- **Pricing** — [`GET https://api.malibu.tech/v1/rate-card`](https://api.malibu.tech/v1/rate-card)

Routing picks any eligible provider, so single-request latency varies with which Mac serves you. When a hardware-tier TPS table ships, it will appear here with model, context length, and date.

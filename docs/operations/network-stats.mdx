# Network stats

> The public network snapshot: pool size, volume, capacity estimates, and routability.

The public snapshot behind [malibu.tech/network](https://malibu.tech/network) is:

```
GET https://api.malibu.tech/v1/stats/overview
```

No authentication is needed. `GET https://api.malibu.tech/v1/network-stats` is a compatibility alias that returns the same body. Buyer API reference: [API → Network stats](/api/network-stats).

The gateway caches the snapshot for 30 seconds and limits each client IP to 60 requests per minute per path. `stale_after` is `generated_at` plus 30 seconds.

## Top-level shape

| Key | Contents |
| --- | --- |
| `generated_at`, `stale_after` | Snapshot time and freshness bound (RFC 3339) |
| `network` | Pool, volume and capacity metrics (below) |
| `timeseries` | `rpm_30m` and `tpm_30m` |
| `idle_prewarm` | Idle model-prewarm telemetry (`pool_pct_with_b1_active`, `skips_by_reason_last_1h`) |

## `network` fields

| Field | How it's counted |
| --- | --- |
| `nodes_online` | Connected providers that are ready or busy and pass the serving checks. A free seat is not required. |
| `nodes_hardware_attested` | Online providers with hardware-rooted Apple managed device attestation. A Secure Enclave key on its own does not count. It has no effect on routing or settlement. |
| `models_serving` | Distinct model ids across online providers |
| `requests_total` | Distinct requests with a non-faulted ledger row, all time |
| `tokens_in_total` / `tokens_out_total` | Prompt and completion tokens on those rows, all time |
| `tokens_served_total` | `tokens_in_total + tokens_out_total` |
| `avg_tokens_per_request` | `tokens_served_total ÷ requests_total`, rounded down |
| `network_utilization_pct` | Busy seats as a percentage of all advertised seats, capped at 100 |
| `unified_ram_gb_total` | Sum of reported unified memory |
| `bandwidth_gb_per_s`, `network_power_kw`, `gpu_cores_total`, `cpu_cores_total` | **Estimates** from hardware profiles or provider-reported summaries |
| `capacity_estimate_sources` | Names the source of each capacity figure, so estimates are labelled in the payload |

## `timeseries`

| Series | Buckets | Point shape |
| --- | --- | --- |
| `rpm_30m` | 60 s, last 30 minutes | `{ "t", "value" }`; `value` is `null` for a bucket with no data |
| `tpm_30m` | 60 s, last 30 minutes | `{ "t", "input_tokens", "output_tokens" }` |

## Routability views

For per-model and per-provider detail, with providers under anonymous per-snapshot aliases:

* `GET https://api.malibu.tech/v1/stats/routability`
* `GET https://api.malibu.tech/v1/stats/models`
* `GET https://api.malibu.tech/v1/stats/providers`

Field definitions: [Reputation → Public routability snapshot](/network/reputation#public-routability-snapshot).

## Warm models vs rate card vs catalog

These three lists are different:

| Surface | What it shows |
| --- | --- |
| `GET https://api.malibu.tech/v1/models` (bearer) | Models with **at least one routable provider right now** |
| `GET https://api.malibu.tech/v1/rate-card` | Models the network **will bill** (signed pricing rows) |
| Signed catalog feed | Models providers **may load** (hash, RAM tier, benchmark gates) |

A model can have a rate-card row and no provider online. Requests for it return `404 model_not_found` until a Mac loads that model.

## Receipts and settlement

Receipt verdicts drive [verified model settlement](/operations/verified-model-settlement). The overview does **not** publish a receipt validity rate. The per-provider routability view reports only whether each provider's receipt key is on record.
